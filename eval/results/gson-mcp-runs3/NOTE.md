# Baseline for this run lives in `../gson-runs3`

`raw.json` here contains **only `after` records** (5 tasks x 3 runs, query
protocol). That is intentional, not a failed run.

gson was measured under both protocols. The read-protocol run
(`../gson-runs3`) established the bare-repository baseline; the query-protocol
run reused that same baseline rather than re-measuring it, so the two AFTER
columns in the paper's Table 2 are compared against one identical BEFORE. The
other three repositories (`fmt`, `requests`, `cobra`) each carry a fresh,
interleaved baseline in their own directory.

Consequence for this directory's `scoreboard.md`: it reports "5 task(s) had a
BEFORE and/or AFTER run error" and no delta, because the BEFORE side is absent
here by design. Read that scoreboard for the AFTER token counts only. The
paired numbers are in the paper's Table 2 and are regenerated by:

```
PYTHONPATH=src python eval/pool_stats.py
```

which pairs this directory's AFTER against `../gson-runs3`'s BEFORE explicitly.

This baseline reuse is disclosed in the paper's Threats to Validity section
("Baseline reuse") and in `ARTIFACT.md`.
